# Google Apps Script Backend

This folder contains the Google Sheets backend deliverables for IQMS for RZ-Circular.

## Purpose

- Keep Google Sheets behind a clean API layer
- Avoid hard-coding column positions in the frontend
- Support future Google Drive file storage for PO photos and packing slip PDFs
- Provide a migration step between the demo build and a fuller production backend

## Included here

- `SheetSchema.md`: current sheet/tab structure for IQMS
- `Code.gs`: Apps Script scaffold with route handlers for dashboard, search, receive with quick quality decisions, pack, damage, repair, unpack, file metadata, and PDF slip generation
- `appsscript.json`: deployment metadata

## Current state

The live demo in this workspace uses the local repository by default. The Apps Script files are intended as the integration boundary for:

- users and roles
- locations and shelves
- lookups
- search
- inventory reads
- transactions and audit trail
- grouped receipts with direct shelf placement and quick quality results
- packing orders and PDF logging
- uploaded file metadata
- Google Drive-backed PO photos and packing slips when folder IDs are configured

## Recommended production approach

1. Use Google Sign-In for authorised users
2. Keep the `Users` sheet as the role/location authorisation table
3. Let Apps Script validate every stock movement before writing to Sheets
4. Store PO photo and packing slip file metadata in Sheets
5. Store the actual files in Google Drive when required

## Deployment steps

1. Create the spreadsheet tabs from [SheetSchema.md](./SheetSchema.md)
2. Open Apps Script from the spreadsheet
3. Paste `Code.gs`
4. Add Script Properties:
   - `SPREADSHEET_ID`
   - `API_TOKEN`
   - `UPLOADS_FOLDER_ID` if PO photos should be stored in Drive
   - `PDF_FOLDER_ID` if packing slips should be stored in Drive
5. Deploy as a Web App
6. Copy the deployment URL into `.env` as `GOOGLE_APPS_SCRIPT_URL`
7. Set `GOOGLE_APPS_SCRIPT_TOKEN`
8. Change `DATA_SOURCE=apps-script`

## Current operational model

- `Receive` combines PO capture, quick quality decision, and direct shelf placement.
- `Search` is one unified screen for shelf search and item search.
- `Inbound` and `Cycle Count` are not part of the current UI flow.
- Shelf entry is scan-first and dropdown-backed across shelf-based workflows.

## Demo identity bootstrap

- If the `Users` sheet is empty, the Apps Script layer automatically seeds the required demo users for:
  - `admin@rz-circular.com`
  - `supervisor@rz-circular.com`
  - `operator@rz-circular.com`
- The seeded passwords are stored as scrypt hashes generated by the app, not as plain text.
- The same bootstrap also inserts the matching `Roles` and `Locations` rows when those tabs are empty.
- You can also trigger the same bootstrap manually through the Apps Script route `?path=initialiseDemoUsers&token=...`.

## Important note

The current scaffold now mirrors the main operational flows, but the local adapter remains the fastest reference when extending business rules further. Keep the two aligned if you change:

- `lib/data/adapters/local.ts`
- `lib/data/operations.ts`
